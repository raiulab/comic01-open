# イラスト修正 Inpaint の原因分析と修正方針

## 問題

イラスト修正モードの Inpaint で、ユーザーの修正プロンプトがほとんど反映されない。

## 原因分析

### 1. モデルの仕様上の制約（根本原因）

- **Gemini の画像モデル（gemini-3-pro-image-preview）は Inpaint 専用ではない**
  - 本来は「画像生成」用。マスクベースの編集（inpainting）をネイティブではサポートしていない
  - Google のネイティブ Inpaint は **Imagen Edit API（Vertex AI）** で提供されており、本プロジェクトの Google AI（Generative Language）API とは別
  - 現状は「2枚の画像＋テキスト」を渡し、プロンプトで「白マスク部分だけ編集」と指示している「疑似的な Inpaint」

### 2. プロンプトの構造上の問題

- **ユーザー指示の優先度が弱い**
  - 「【最重要・最優先】」と書いても、その後に「画風の維持」「絶対に守ること」など多数のルールがあり、モデルがユーザー指示よりルールを優先する可能性
- **コンテンツの送信順**
  - 現状: `[元画像パッチ, マスク画像, テキストプロンプト]`
  - タスク説明が最後に来るため、モデルが「何をすべきか」を後から解釈する形になり、誤解や無視が起きやすい
- **指示の曖昧さ**
  - ユーザーが「笑顔に変えて」「目を閉じて」など短い指示を出すと、マスク領域内の「何を」「どう」変えるかがモデルに伝わりにくい

### 3. マスクの解釈

- 二値化マスク: 白=編集対象、黒=変更禁止
- プロンプトで説明しているが、モデルの学習データにこの形式が少ない可能性
- 英語で「INPAINTING: white=edit, black=preserve」と明示すると、理解が安定することがある

### 4. パッチ単位での送信

- マスクのバウンディングボックスで切り出した「パッチ」のみを送信
- 周辺コンテキストが欠け、モデルが「どこに何を描くか」を把握しづらい場合がある
- ただし、フル画像を送るとトークン消費・応答サイズが増える

## 修正方針

### A. プロンプトの強化（即効性あり）

1. **テキストを先頭に送る**
   `[テキストプロンプト, 元画像, マスク画像]` の順に変更し、タスクを最初に伝える
2. **ユーザー指示を最前面に**
   ユーザーの修正指示を冒頭に置き、重複ルールは後ろに集約
3. **技術指示を英語で補足**
   「INPAINTING TASK. Image1=source, Image2=mask (WHITE=edit, BLACK=preserve). Output=same size, only white area changed.」
4. **出力形式を明示**
   「返す画像は1枚目と同一サイズであること」を必ず含める

### B. 短い指示の展開（オプション）

- ユーザー指示が短い（例: 50文字未満）場合、テキストモデルで「具体的な編集内容」に展開してから画像モデルに渡す
- 例: 「笑顔に変えて」→「マスクされた顔の部分を、目を細め、口角を上げた笑顔の表情に変更する。髪型・服装・画風は元画像のまま維持する。」

### C. 将来の検討（Vertex AI 移行）

- Imagen Edit API（Vertex AI）への移行で、ネイティブ Inpaint を利用可能
- 設定変更や認証周りの改修が必要

## 実装する修正（A + B の軽量版）

- プロンプトの構造見直し（A）
- イラストモード時に短い指示をテキストモデルで展開（B の簡易版）
