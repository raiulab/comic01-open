# カスタマイズルール - 必ず守るべき重要事項

このドキュメントは、RAIU Agentプロジェクトで実装された重要なカスタマイズ機能のルールをまとめたものです。
**今後のカスタマイズやコード変更時には、これらのルールが上書きされないよう必ず確認してください。**

---

## 1. AIによる構成シナリオ生成時の遵守事項

### 1.1 エンドポイント
- **エンドポイント**: `POST /api/comics/:date/suggest_structure`
- **ファイル**: `server/index.js` (1681行目〜)

### 1.2 必須遵守事項

#### キャラクター制限
- **【厳守】** エピソード概要に登場させるキャラクターは、以下のみ：
  - 人間の大人
  - 子供
  - 設定で登録したキャラクター（`characters`テーブルに登録済み）
- **【厳守】** 上記以外のキャラ（動物・架空の存在など）は登場させないこと

#### 人間とキャラクターの関係性
- **【厳守】** 登場する人間（大人や子供たち）は、登録済みキャラクターの名前を呼ばないこと
- 人間とキャラクター（動物や神さま、精霊など）は別の次元で暮らしているため
- 子どもとキャラクターたちは近い領域に存在するが、言葉を交わし合うことはない
- 構成・セリフの中でもこの関係を守ること

#### 各コマのcontent形式（必須）
各コマの`content`は以下の形式で**必ず記述すること**：

```
1. 構図〈構図：構図の説明〉
   - カメラアングル、構図の種類（アップ、ロング、ワイドなど）を簡潔に
   - 例: 構図〈構図：アップショット、キャラクターの顔を中心に〉

2. シーン説明
   - 誰が何をしているか、場面の状況を説明
   - 例: 公園で子供たちが遊んでいる。そうべいが遠くから見守っている。

3. セリフ【発話者：セリフ内容】（セリフがある場合のみ）
   - セリフがある場合のみ記載。かっこ（）は使わないこと
   - **【厳守】セリフはひらがな・カタカナ・アルファベット・数字で表記すること。漢字は使わないこと。構成に書いた文字は画像にそのまま描画される**
   - 例: 【そうべい：おい、そこのきのこ〜】【子供たち：わあ〜】
   - 誤り例: 【子供A：（こうないえん…？）】→ 正しくは【子供A：こうないえん…？】
   - セリフはできるだけ短くすること。画像生成時に1コマに収まる長さを考慮し、必要最小限の文字数にすること
   - セリフがないコマは、この項目を省略すること
```

#### セリフの記述形式
- 各コマの`content`内でセリフを書くときは、**【発話者：セリフ】**の形式で記述すること
- **セリフはひらがな・カタカナ・アルファベット・数字で表記すること。漢字は使わないこと。構成に書いた文字は画像にそのまま描画される**
- かっこ（）は使わないこと
- セリフはできるだけ短くすること

#### アスペクト比の扱い
- `content`の文章の中に、コマの縦横比を表すフレーズ（「アスペクト：landscape」など）は書かないこと
- 比率は別項目`aspect`で指定するので、`content`には含めないこと

#### コマの種類
- 必要に応じて、第3者視点で「状況を説明する文字だけのコマ」を挿入してよい
- その場合は`content`に説明文を記載し、`aspect`を指定すること（例: ナレーションや地の文のみのコマ）

#### マンガの構成の基本（シリーズ設定）
- 設定の「シリーズ設定（JSON）」に `composition_basis` と `composition_rules` を指定できる
- **構成の基本（composition_basis）**: 4コマの流れを定義する。例: 1) 猫が寝/散歩していると人の話し声が聞こえる 2) 話が続く 3) 話に展開。猫はそのまま。登録キャラ登場可 4) 話が続く、または静かな余韻。猫はそのまま
- **構成ルール（composition_rules）**: 描画上のルール。例: 猫の表情は特に変わらない。人の顔は特に描かなくてよい。セリフだけでもよい
- `suggest_structure` では上記をプロンプトに含め、画像生成では `composition_rules` をプロンプトに含める
- サンプル: `config/series-concept.example.json`

## 2. 構成シナリオに忠実にまんが画像を生成するための遵守事項

### 2.1 エンドポイント
- **エンドポイント**: `POST /api/comics/:date/generate`
- **ファイル**: `server/index.js` (1773行目〜)

### 2.2 必須遵守事項

#### コマの枠線
- **コマの枠線は手書き風のやや歪んだ線で引くこと**
- 完璧な直線ではなく引くこと
- 画像の上端・下端・左右の端まで必ず引くこと

#### キャラクター名・話者名の表記禁止
- **【絶対厳守】** キャラクター名・話者名（例：子供A、〇〇、ひと）は画像内に**絶対に表記しないこと**
- **吹き出し内には「ひと：」などの話者名を絶対に書かないこと。** セリフ内容のみを描くこと。
- セリフや吹き出しは描かないでください
- 画像生成プロンプトに明示的に記載すること（複数箇所）

#### 主役が話さない設定（黒ねこなど）
- シリーズ設定（concept_config）で `main_character.speaks === false` の場合、主役のキャラ（例：黒ねこ）は**話さない**設定とする
- 画像生成プロンプトに「主役の黒ねこ（主役の猫）からは吹き出しを絶対に出さないこと」を自動で追加する（`server/index.js` の 4コマ一括生成・1コマ再生成の両方）
- これにより、黒猫からセリフの吹き出しが出ているまんが画像が生成されないようにする

#### 画像サイズとレイアウト
- 4コマ漫画を1枚の縦長画像で描くこと
- 上から1コマ目・2コマ目・3コマ目・4コマ目の順に縦に並べる
- 各コマの縦横比の指定がある場合は、それに合わせてコマの高さを調整してよい
- 1枚の画像の中に4コマを縦に並べ、コマ割りの枠を画像サイズいっぱいまで広げること
- 全コマのイラストが切れずにすべて表示されること

#### 6コマ以上で2枚に分かれる場合の日付記載
- **6コマ以上の生成で漫画画像が2枚以上に分かれる場合**、**2枚目以降の冒頭の「文字だけのコマ」には日付を記載しないこと**
- 日付（〇〇年〇〇月〇〇日）は1枚目のストリップの冒頭の文字だけコマにのみ記載する
- 2枚目以降のストリップの冒頭が文字だけコマの場合でも、日付は書かない（地の文・ナレーションのみ）
- 実装: `buildCombinedPanelImagePrompt` の `chunkIndex` パラメータで制御（chunkIndex > 0 のときは日付を追加しない）

#### 背景
- 背景は白またはシンプルに

#### まんが生成の画風（厳守）
- まんが生成・再生成・Inpaint のいずれも **画風の優先順位** を守ること
- **優先順位**: 1) 設定の「画風設定」（image_style_config + image_style_selected）で指定したスタイルを厳守 → 2) 未設定ならシリーズ設定の `art_style` を厳守 → 3) それもなければ `drawing_style` 設定 → 4) デフォルト
- 実装: `getEffectiveDrawingStyleForComic()`（`server/index.js`）が上記の順で画風文言を返す。生成・再生成・Inpaint では必ずこの関数の戻り値を【画風】（厳守）に挿入すること
- 画風設定がある場合は「【厳守】設定の「画風設定」で指定した以下の指示を厳密に守ること」を前置し、art_style 等のフォールバック時は「【厳守】以下の画風（シリーズ設定の art_style または画風のデフォルト）を厳密に守ること」を前置すること

## 3. 設定で登録したキャラクター画像を指定の画風にアレンジしてまんが画像を生成するための遵守事項

### 3.1 キャラクター参照画像の自動追加ロジック
- **ファイル**: `server/index.js` (1890行目〜)
- エピソード概要や構成シナリオに登録済みキャラクター名が含まれる場合、自動的にそのキャラクターの参照画像を追加する
- `getCharactersMentionedInText`関数でテキストからキャラクター名を検出
- `selected_characters`で明示的に選択されたキャラクターも含める

### 3.2 キャラクター描画ルール（絶対厳守）

画像生成プロンプトに以下のルールを**必ず含めること**：

```
【キャラクター描画ルール - 必ず遵守すること】
1. 参照画像で渡したキャラクターは、必ず上記の【画風】設定に変換してイラストとして描くこと
2. キャラクターの外見的特徴（髪型・髪色・服装・体型・顔の特徴・アクセサリー）は参照画像に忠実に維持すること
3. ただし描画タッチ・線の太さ・陰影・色使いは【画風】の指定に完全に従うこと
4. 参照画像をそのままコピーせず、各コマのシーンに合わせてポーズや表情を変えること
5. 同一キャラクターは全コマで外見の一貫性を保つこと（服装・髪型が変わらないこと）
6. キャラクター名や話者名（例：子供A、〇〇）を画像内に文字として絶対に表記しないこと
```

### 3.3 キャラクター属性の活用
- **ファイル**: `server/index.js` (1693行目)
- `getCharacterInfoFromSummary`関数で、エピソード概要に含まれるキャラクター名から属性情報を取得
- キャラクターの属性（`characters.description`）を画像生成プロンプトに含める
- 形式: `登場キャラクター（以下の属性を前提にシナリオ・構図を考えてください）:\n- キャラクター名: 属性`

## 4. 調整（Inpaint）後の生成画像のサイズ

### 4.1 エンドポイント
- **エンドポイント**: `POST /api/comics/:date/inpaint`
- **ファイル**: `server/index.js` (3318行目〜)

### 4.2 サイズ維持の仕組み（方針B）

#### 基本方針
- **Inpaint後の画像サイズは、元の画像サイズと完全に一致させること**
- 画像の縮小や拡大による画質劣化を防ぐため

#### 実装方法（4コマ結合画像の場合）
1. **元画像のサイズ取得**
   - `sharp`で元画像のメタデータから`originalWidth`と`originalHeight`を取得
   - デフォルト値: `PANEL_SIZE` (512px) × `COMBINED_PANEL_HEIGHT` (2048px)

2. **パネル矩形の計算**
   - `getPanelRectsForStrip`関数で、各パネルの`top`と`height`を計算
   - `comic.summary`から各パネルの`aspect`を取得し、比率に基づいて高さを計算

3. **対象パネルの切り出し**
   - `sharp().extract()`で、元画像とマスク画像から対象パネル領域のみを切り出し
   - `left: 0, top: rect.top, width: originalWidth, height: rect.height`

4. **Inpaint処理**
   - 切り出したパネル領域のみをAIに送信（トークン消費削減）
   - `generatePanelImageWithGemini`でInpaint実行

5. **サイズ調整と貼り戻し**
   - Inpaint結果を`originalWidth × rect.height`にリサイズ（`fit: 'cover'`）
   - `sharp().composite()`で元のストリップ画像に貼り戻し
   - 最終的な画像サイズは`originalWidth × originalHeight`を維持

#### 注意事項
- マスク座標との整合性を保つため、パネル矩形の計算は正確に行うこと
- 8コマ漫画など複数ストリップの場合も、各ストリップごとに同じロジックを適用
- ストリップベースの処理により、座標の一貫性が保たれる

## 5. 漫画の読順・表示順序（右から左）

**詳細は `docs/COMIC_READING_ORDER.md` を参照すること。以下は必ず守る。**

### 5.1 基本原則
- **日本の漫画の読順**: 右→左、上→下。左右に並んだコマは**右が前・左が後**。
- コマの配置・エクスポートは**プログラムで明示的に指定**すること（AIの出力順に依存しない）。

### 5.2 2×2レイアウト（エクスポート `?layout=2x2`）
- **右列（画像の右半分）**: 1コマ目（上）、2コマ目（下）
- **左列（画像の左半分）**: 3コマ目（上）、4コマ目（下）
- 読順: 1 → 2 → 3 → 4
- 実装: `server/index.js` の `GET /api/comics/:date/export` で `composite` の並びを上記のとおり固定すること。

### 5.3 1コマ内のセリフ（吹き出し）
- 先に読むセリフ → **右側**、後に読むセリフ → **左側**
- 実装: `client/src/utils/serifOverlay.js`（偶数番目→右、奇数番目→左）、および画像生成プロンプトで同旨を明示。

## 6. コマの縦横比率設定

### 6.1 サポートされている比率
- **既存の3つ**:
  - `landscape`: 4:1（横長）
  - `square`: 1:1（正方形）
  - `portrait`: 1:4（縦長）
- **新しい比率形式**:
  - `4:1`, `2:1`, `4:3`, `3:4`, `1:2`, `1:4`

### 6.2 実装箇所
- **サーバー側**: `server/index.js`
  - `aspectToRatio`関数（332行目、441行目）
  - アスペクト比検証ロジック（複数箇所）
- **クライアント側**:
  - `PrepareTab.jsx`: UI選択肢
  - `serifOverlay.js`: `aspectToHeightRatio`関数、`getPanelBounds`関数

### 6.3 画像サイズ計算
- **幅**: 固定で`PANEL_SIZE` (512px)
- **高さ**: 各コマのアスペクト比に基づいて動的に計算
  - 1コマあたりの高さ = `PANEL_SIZE * (ratio.h / ratio.w)`
  - 合計高さ = 各コマの高さの合計
- **制限**:
  - 最小高さ: `PANEL_SIZE * 2` (1024px)
  - 最大高さ: `PANEL_SIZE * 10` (5120px)

### 6.4 注意事項
- APIの実際の画像生成サイズ制限を考慮すること
  - Gemini API: 1024×1024px固定
  - DALL-E 3: 最大1792×1024または1024×1792
- `targetHeight`がAPI制限を超える場合、`normalizeCombinedImageBuffer`でスケールされる（`fit: 'contain'`）

## 7. セリフオーバーレイ機能

### 7.1 基本方針
- **【重要】** 画像生成時には「セリフや吹き出しは描かない」という指示があるため、生成された画像にはセリフが含まれていない
- **【重要】** 出力タブでは、必ずセリフオーバーレイを適用してセリフを表示すること
- セリフは構成シナリオ（`comic.summary`）から抽出し、Canvas上に描画する

### 7.2 セリフ抽出
- **ファイル**: `client/src/utils/serifOverlay.js`
- **関数**: `parseSerifFromContent`
- **【重要】セリフとして認識するのは【】で囲んだ部分のみ**
  - 構成の説明で使う「」（鍵括弧）はセリフとして抽出しない（誤認識防止）
- **形式**: `【発話者：セリフ】`（全角【】または半角[]・コロンの揺れに対応）
- **構図の除外**: `構図〈構図：〜〉`の形式はセリフとして誤認識されないよう、事前に除外する
- **抽出パターン**（上記のみ。「」形式・行頭形式は使用しない）:
  - `【発話者：セリフ】`（全角【】）
  - `[発話者:セリフ]`（半角[]、または正規化後の【】）

### 7.3 パネル境界の計算
- **ファイル**: `client/src/utils/serifOverlay.js`
- **関数**: `getPanelBounds`
- **【重要】常に等分割を使用**: アスペクト比に関係なく、コマ数に基づいて画像を等分割する
- これにより、セリフオーバーレイが確実に動作し、アスペクト比の複雑な計算による問題を回避
- 各コマの高さ = `Math.floor(imageHeight / コマ数)`
- 最後のコマは残りの高さを全て使用（端数処理）

### 7.4 描画（参考画像に合わせた仕様）
- **ファイル**: `client/src/utils/serifOverlay.js`
- **関数**: `drawSerifOverlay`, `drawBubbleAndText`, `drawSingleBubble`
- **配置**: コマ上部の吹き出しゾーンのみ（高さの約25%）に配置し、イラストと重ならないようにする
- **左右振り分け**: 1本目は左、2本目は右と交互に配置し、中央に余白を残してキャラが隠れないようにする
- **しっぽの向き**: 左列は左下方向、右列は右下方向にしっぽを描画（話者方向を指す）
- **吹き出しの形**: 角丸四角（四隅で半径を少しずらした手描き風）と楕円をランダムに使用
- **スタイル**: 白背景の吹き出し（`rgba(255,255,255,0.98)`）と黒いテキスト（`#000`）
- **フォント**: 日本語フォントスタック。フォントサイズはコマ高さに応じてスケール（12〜18px）

### 7.5 出力タブでの適用
- **ファイル**: `client/src/components/OutputTab.jsx`
- **必須**: 出力タブでは必ずセリフオーバーレイを適用すること
- **処理フロー**:
  1. `comic.summary`から各コマの`content`を取得
  2. `parseSerifFromContent`でセリフを抽出
  3. `getPanelBounds`でコマ境界を計算
  4. `drawSerifOverlay`でセリフを描画
  5. CanvasをData URLに変換して表示・ダウンロード可能にする
- **エラーハンドリング**: セリフ抽出に失敗した場合は、画像をそのまま表示（セリフなし）

### 7.6 Inpaint時の注意（画風参照を送らない）
- **【厳守】Inpaint API には画風参照画像（ref_style_image_path）を送らないこと**
- 送るとモデルが参照画風で全体を描き換え、画像が「画風参照画像」のタッチに変わったり、セリフが消えたように見える不具合の原因になる
- Inpaint では「元画像＋マスク＋テキストプロンプト」のみを送り、プロンプトで「元の画像の画風・タッチをそのまま維持すること」を明示する
- 該当: `server/index.js` の `POST /api/comics/:date/inpaint`

### 7.7 Inpaint後のセリフ処理
- Inpaintプロンプトで「元画像にセリフが含まれている場合は完全に除去する」と指示
- Inpaint後の画像にはセリフが含まれていないため、出力タブでセリフオーバーレイを適用する必要がある

### 7.8 セリフ検出状態の可視化と警告機能
- **ファイル**: `client/src/components/OutputTab.jsx`
- **機能**: 各出力画像のセリフ検出状態を視覚的に表示
- **状態タイプ**:
  - `success`: セリフが正常に検出・表示された（緑色）
  - `warning`: セリフが期待されるが検出されなかった（黄色）
  - `error`: セリフオーバーレイの適用に失敗した（赤色）
  - `info`: セリフがないことが正常な状態（青色）
- **表示内容**:
  - セリフ検出件数とコマ数
  - エラーメッセージ（エラー時）
  - セリフ形式のヒント（警告時）

### 7.9 セリフ検出失敗時の自動診断
- **診断項目**:
  - 構成シナリオ（summary）が存在するか
  - 各コマのcontentにセリフ形式のヒント（【】または[]）が含まれているか
  - セリフ抽出関数が正しく動作しているか
  - パネル境界の計算が成功しているか
- **ログ出力**: コンソールに詳細な診断情報を出力（デバッグ用）

- [ ] セリフ検出失敗時の診断情報がログに出力されているか
- [ ] **コマ・セリフの左右配置が「右=前・左=後」の読順になっているか**（`docs/COMIC_READING_ORDER.md` 参照）
