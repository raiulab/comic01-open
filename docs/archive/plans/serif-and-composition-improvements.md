# セリフ二重認識・未来日時カタカナ・人情要素の修正・追加 設計方針

## 1. セリフのスペースによる二重認識の解消

### 原因
- `parseSerifFromContent` は「全角【】」と「正規化後[]」の両方で同じ content をマッチしている。
- 正規化で全角スペース（　）が半角スペースに変換されるため、**同一セリフ**が「こんにちは　世界」（全角スペース）と「こんにちは 世界」（半角スペース）の2通りでマッチする。
- 重複排除の key が `speaker:text` のため、スペースの違いで key が異なり、両方とも results に入る。

### 設計方針
- **重複判定用の key を正規化する**: セリフ文字列の空白（全角・半角・連続スペース）を単一の半角スペースに揃え、前後トリムした文字列で key を生成する。
- **results に格納する text は最初にマッチした生の文字列のまま**とする（表示・描画は従来どおり）。

### 変更箇所
- `client/src/utils/serifOverlay.js` の `parseSerifFromContent` 内:
  - `key = \`${speaker}:${text}\`` を、正規化 key に変更: 空白を `\s+` で単一スペース化し trim した値で `seenMatches` を判定。
  - 既に同じ正規化 key が登録されていればスキップし、初出のときだけ `results.push({ speaker, text })` する。

## 2. 未来の日時の構成シナリオでセリフが全てカタカナになる問題の解消

### 原因
- プロンプトでは「セリフは全てひらがなとカタカナだけで表記」とだけ指定しており、**ひらがな主体**の指示がない。
- 未来日付の文脈では AI が「未来的・機械的」なトーンでカタカナ多用しがち。

### 設計方針
- 構成シナリオ用プロンプトに、**セリフ表記の優先順位**を明示する一文を追加する:
  - セリフは**ひらがなを主体**とし、カタカナは外来語・固有名詞など必要な場合のみ使うこと。
  - セリフ全体をカタカナだけにしないこと。日常の会話はひらがな中心で書くこと。

### 変更箇所
- `server/index.js` の `POST /api/comics/:date/suggest_structure` 内の「セリフ【発話者：セリフ内容】」の注意書き:
  - 既存の「【厳守】セリフは全てひらがなとカタカナだけで表記すること。漢字は使わないこと。」の直後に、上記のひらがな主体・カタカナのみ禁止の指示を追加する。

## 3. 構成シナリオに人情・情緒・いとおしさを加える

### 目的
- 読者がほっこりしたり、心が温かくなるような描写を AI に意識させる。

### 設計方針
- 構成シナリオ生成プロンプトの「マンガの基本設定・トーン」または「要件」に、**人情・情緒・いとおしさ**を明示する一文を追加する:
  - 各コマの状況やセリフには、人情味、情緒、いとおしさを感じさせる要素を盛り込むこと。
  - 読者がほっこりしたり、心が温かくなるような描写を心がけること。

### 変更箇所
- `server/index.js` の `POST /api/comics/:date/suggest_structure` 内:
  - 【マンガの基本設定・トーン】のブロックの末尾に、上記の指示を追加する。
