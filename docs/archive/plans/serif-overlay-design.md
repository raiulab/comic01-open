# まんが画像へのセリフ挿入 設計方針

## 現状

- 画像生成プロンプトで **「セリフや吹き出しは描かないでください」** と指示しているため、生成画像は**絵だけ**で、セリフは含まれていない。
- シナリオ（構成）には **【発話者：セリフ】** 形式でセリフが入っており、コマごとの `description`（または `content`）で参照可能。

## 方針の候補

### 方針A: AI にセリフ・吹き出しを描かせる

- プロンプトを変更し、「各コマのセリフは吹き出し内に描くこと」とし、`plan.description` のセリフをプロンプトに含める。
- **メリット**: 実装が単純（プロンプト変更のみ）。
- **デメリット**:
  - 画像生成AI（Gemini / DALL-E）は**文字描画が苦手**で、日本語は崩れ・誤字・読めないことが多い。
  - 指定した文言と異なるテキストが描かれる可能性が高い。
  - 「指定のコマに必ず入れる」を保証しにくい。

→ **セリフの正確性・可読性を重視するなら非推奨。**

---

### 方針B: 後処理で吹き出し＋テキストをオーバーレイする（推奨）

- 画像生成は**現状どおり「セリフを描かない」**ままにする。
- 生成後に、**シナリオのセリフをパースして、該当コマに吹き出しとテキストを描き足す**。

**メリット**

- シナリオに書かれた文言が**そのまま**表示されるため、誤字・内容のずれがない。
- フォント・サイズ・改行をこちらで制御でき、可読性を確保しやすい。
- コマの範囲が分かれば「指定のコマに必ず挿入」を実現しやすい。

**必要な処理**

1. **セリフの抽出**
   - 各コマの `description`（または `content`）から **【発話者：セリフ】** を正規表現で抽出。
   - 例: `【そうべい：おい、そこのきのこ〜】【子供たち：わあ〜】` → 2件の「セリフ文」の配列。
2. **コマ領域の算出**
   - 4コマ縦1枚の場合、各コマのアスペクト（landscape / square / portrait）から高さの比率を計算し、画像内の Y 範囲（上端〜下端）を算出。
   - 幅は画像幅いっぱい（または PANEL_SIZE）で固定。
3. **描画**
   - 各コマ領域内に「吹き出し（円・角丸四角など）」と「テキスト」を描画。
   - 日本語フォントが必要。

**実装場所の候補**

| 方式 | 説明 | メリット | デメリット |
|------|------|----------|------------|
| **サーバー側** | Node で画像を読み、Sharp / node-canvas 等で吹き出し＋文字を描画し、1枚画像として保存・返却 | 1回のリクエストで「セリフ入り画像」が手に入る | 日本語フォントの配置・パス管理が必要 |
| **クライアント側** | 生成画像＋コマ別セリフJSON を渡し、Canvas で吹き出し＋テキストを描画して表示・エクスポート | フォントはブラウザ／OS 任せでよい | 表示時は可能だが、「保存用セリフ入り画像」を出すにはエクスポート処理が必要 |

**推奨**:
- **表示**はクライアント側オーバーレイで実装（フォント問題を避けつつ、すぐ試せる）。
- **保存用の「セリフ入り1枚画像」**が必要なら、サーバー側でフォントを用意し、同じロジック（コマ領域＋セリフ抽出）で描画する API を追加する。

---

## 推奨する進め方（方針B）

1. **共通: セリフ抽出**
   - `description` 文字列から `【○○：△△】` をパースする関数を用意（サーバー・クライアントどちらでも使えるように）。
2. **コマ領域の算出**
   - 4コマ縦1枚のとき、アスペクト比の配列から各コマの高さを計算し、`(y0, height)` または `(y0, y1)` のリストを返す。画像幅は固定。
3. **クライアント側オーバーレイ（第一期）**
   - 出力タブで「画像 ＋ コマ別セリフ」を受け取り、Canvas 上に吹き出し＋テキストを描画して表示。
   - 必要なら「セリフ入り画像をダウンロード」で Canvas を PNG 出力。
4. **（任意）サーバー側レンダリング**
   - 「セリフ入り画像を1枚で保存したい」需要があれば、上記と同じルールでサーバー側に描画 API を追加し、日本語フォント（例: Noto Sans JP）をサーバーに配置する。

---

## まとめ

- **「シナリオのセリフを指定コマに必ず入れ、かつ正しい文言で表示する」**ためには、
  **方針B（後処理オーバーレイ）** が適切。
- まずは **セリフ抽出ロジック** と **クライアント側の吹き出し・テキスト描画** から実装し、表示で検証するのがよい。
